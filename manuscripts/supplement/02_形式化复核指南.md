# 形式化复核指南

本附件对应第一篇研究论文的第6节。复核对象是v1.0 源码归档，不是根据文章中的名称重新编写的一套证明。

## 1. 运行位置与命令

进入 v1.0 源码归档的仓库根目录，使用 `lean-toolchain` 指定的 Lean `v4.35.0-rc2`。项目不依赖 Mathlib。

```text
lake build
lake env lean lean/Surangama/SevenLocations/Audit.lean
python tools/check_scope.py
python tools/check_shared_nonduality.py
```

第一项构建项目，第二项输出所列定理的公理依赖，后两项分别核查原有逐段模型与共同模型的布尔赋值。Python 枚举的是脚本中明确转写的公式，不是直接运行 Lean 的语义；二者是否对应也需要检查。

`audit/propositional-scope.json` 与 `audit/shared-nonduality-scope.json` 对应正文表3。当前共同三变量模型一共有8种赋值，其中4种满足前提；不是84种赋值。七个省略连接条件的检查是另外列出的七个见证，不能混进“8种赋值”的计数。

## 2. 共同模块的八个声明

命名空间：`Surangama.SevenLocations.SharedNonduality`。

| 定理名 | 作用 |
|:--|:--|
| `bridge_for_each` | 用七个章节构造子逐项取出已提供的连接条件；不证明连接的文本真实性 |
| `exclude_identification` | 从共同排除和单个连接推出描述与认定不能同时成立 |
| `seven_identifications_refuted` | 将该条件推导应用于全部七个索引 |
| `refute_contextual_claim` | 在补充 `Claim → Description ∧ Identifies` 后，转到另行命名的主张 |
| `premises_have_model_with_descriptions` | 给出前提可同时满足、且描述都成立的见证 |
| `without_common_exclusion` | 删除共同排除后，七条连接并不能单独排除七个认定 |
| `without_one_bridge` | 对任一索引，删除该处连接即可保留该处认定，即使其他连接仍在 |
| `description_can_remain` | 说明排除“描述且认定”不等于排除描述本身 |

这八个声明包含辅助证明与范围见证，不能写成八项独立佛学发现。论文摘录的 `exclude_identification` 代码保持与源文件一致。

## 3. 三个符号与两类前提

`Description i` 表示选定的候选描述成立；`Separated i` 特指将能知者实体化为与对象分立的自存者；`Identifies i` 表示该候选被正确认定为对话所求的心性。

共同排除条件是：

```text
Separated i → ¬ Identifies i
```

逐段连接条件是：

```text
Description i → Separated i
```

结论是：

```text
¬ (Description i ∧ Identifies i)
```

`¬` 表示否定，`→` 表示蕴含，`∧` 表示合取。`Separated` 不是单指空间分离、功能区分或依缘而生；不能缩略成“凡有能所分别就错误”。

## 4. 证据与版本

`verification.json` 保存实际构建和检查的结果，相关日志在同目录。论文目录的 `MANIFEST.sha256` 保存公开稿件文件散列；源码以 v1.0 标签标识。

v1.0 包含共同模块，旧 v0.2.1 归档保持不变。共同模块不能追溯归入旧版 DOI；本次公开排版不改变证明的假设。
